# FileStorage

**FileStorage** — механизм, позволяющий системе загружать, хранить, получать файлы и управлять ими.

Бизнес-примеры:

* пользователи загружают в систему документы или изображения;
* приложение формирует файлы (отчёты, выгрузки, шаблоны);
* внешние системы присылают файлы, которые нужно сохранить;
* шаги бизнес-процесса требуют прикрепления или получения документов;
* файлы нужно хранить в разных хранилищах в зависимости от бизнес-правил.

При загрузке можно передать параметр source, который позволяет бизнес-процессам динамически решать, в каком хранилище сохранить файл в зависимости от правил процесса.

Такая гибкость позволяет настраивать стратегии хранения в соответствии с логикой предметной области, не меняя поведение для пользователя.

## Как добавить? { #how-to-add }
(начиная с [релиза 2.0.9](https://doc.cxbox.org/ru/new/version209/))

### extends AbstractCxboxFileController

`AbstractCxboxFileController` — базовый контроллер, предоставляющий REST-эндпоинты для загрузки, скачивания и удаления файлов.
Все операции с файлами он делегирует `CxboxFileService`.

Этот класс реализует `CxboxFileController`; его следует наследовать в конкретных контроллерах, а не использовать напрямую.

Унаследуйте этот абстрактный класс и пометьте подкласс аннотациями @RestController и request mapping:

```java 
@RestController
@RequestMapping("/api/files")
public class MyFileController extends AbstractCxboxFileController {
}
```
 

### implements CxboxFileService

`CxboxFileService` — абстракция для работы с файлами.
Сервис предоставляет единый интерфейс для загрузки, скачивания и удаления файлов независимо от того, где файлы физически хранятся.

Все операции работают с уникальным идентификатором файла, возвращаемым при загрузке.
Назначение интерфейса: `CxboxFileService` служит точкой расширения. Конкретные реализации определяют, где и как файлы физически хранятся, как генерируются уникальные ID файлов,
какая стратегия хранения используется.

Это позволяет менять хранилище без изменения бизнес-логики приложения.

Методы:

* `upload` — загружает файл в хранилище и возвращает уникальный идентификатор файла.
* `download` — получает файл по его уникальному ID и возвращает его в виде потокового ответа.
* `remove` — удаляет ранее загруженный файл по его уникальному идентификатору.

!!! info
    Если бизнес-процессы требуют загрузки файлов в разные хранилища, эту логику можно разделить, передавая параметр `source`.
    На основании этого параметра система может решить, какое хранилище использовать.
