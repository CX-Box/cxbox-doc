    Signing and encrypting

    (since release 2.0.18)

    Support for signing and encrypting documents using a Qualified Electronic Signature (QES) with CryptoPro software.

    Prerequisites

    To use this functionality, the user must have the required software CryptoPro installed.

    Basic

    Supported:

    • document signing;
    • document encrypting;
    • document signing and encrypting;
    • document encrypting and signing;

    type — operation type:

    Parameter Description
    sign Signing only
    encrypt Encryption only
    encryptAndSign Encrypt first, then sign
    signAndEncrypt Sign first, then encrypt

    Limitations and settings

    File size

    Operation File size
    Detached signature Any
    Encryption Any
    Attached signature Up to 30 MB (30 000 000 bytes)

    Detached signing and encryption process the file in parts, so the file size does not matter. An attached signature is created by the CryptoPro plugin from the whole file at once. The plugin cannot process large files (depending on the computer, it fails at 10–60 MB, see CryptoPro documentation), so the application limits the attached signature to 30 MB.

    The limit is the same for every operation with an attached signature: signing, signing and encrypting, encrypting and signing. When encrypting and signing, the encrypted file is signed, but the limit is still counted against the original file.

    Tips

    If users work with large files, use a detached signature: signaturePackage: detached (default).

    Attached signature of files over 30 MB

    Warning

    We do not recommend removing the limit. Do this only if your project, your information security department and the recipients of the signed documents have agreed on it.

    The limit can be removed with the REACT_APP_CRYPTOPRO_ATTACHED_ASSEMBLY variable. Then the attached signature is created differently: CryptoPro signs the file hash in parts, as for a detached signature, and the application itself inserts the file into the signature container (the pkijs library).

    What changes when the variable is enabled:

    • Every attached signature is created this way, for files of any size, including small ones.
    • The signature container is assembled by the application, not by CryptoPro. The file hash and the signature value are still calculated by CryptoPro, but the container is assembled outside the certified CryptoPro software. If your process requires the signature to be created entirely by certified means (for example, a qualified electronic signature for government information systems), check this before enabling the variable.

    How to enable?

    Example

    Step 1 Add the variable to ui/.env (and to ui/.env.development for the test environment):

    REACT_APP_CRYPTOPRO_ATTACHED_ASSEMBLY = 'true'

    false (default) — an attached signature only for files up to 30 MB. Any value other than true or false is treated as false, and an error is written to the browser console.

    Step 2 Restart the frontend: the variables are read when the frontend is built or started.

    How to remove the assembly from the project?

    Example

    The assembly is a separate optional module ui/src/features/cryptoPro/attachedAssembly. It is loaded only when the variable is enabled. If the project must never create an attached signature this way, remove the module from the build:

    Step 1 Delete all files in ui/src/features/cryptoPro/attachedAssembly except index.ts.

    Step 2 In index.ts, replace the loader with undefined:

    export const loadAttachedAssembly: OptionalModuleLoader<AttachedAssembly> | undefined = undefined

    Step 3 Remove the pkijs and asn1js dependencies from ui/package.json.

    Nothing else changes. If the variable is enabled after that, attached signing fails with the message Attached signature of large files is not included in the application.

    How to add?

    Example

    Step 1 Add a button for signing in the corresponding Service.

        @Override
    public Actions<MyexampleDTO> getActions() {
        return Actions.<MyexampleDTO>builder()
                .create(crt -> crt.text("Create"))
                .delete(dlt -> dlt.text("Delete"))
                .save(sv -> sv.text("Save"))
                .action(act -> act
                        .action("documentSign", "Document Sign")
                        .scope(ActionScope.RECORD)
                        .available(bc -> {
                            return true;
                        })
                        .invoker((bc, dto) -> {
                            Optional<Myexample> myexample = myexampleRepository.findById(Long.valueOf(dto.getId()));
                            myexample.ifPresent(e -> {
                                e.setStatus(StatusSignEnum.SIGNED);
                                myexampleRepository.save(myexample.get());
                            });
                            return new ActionResultDTO<MyexampleDTO>()
                                    .setAction(PostAction.showMessage(
                                            MessageType.INFO, "Action documentSign was invoked"
                                    ));
                        })
                )
                .cancelCreate(ccr -> ccr.text("Cancel"))
                .build();
    }

    Signature Container Format

    The user can choose the format of the generated container:

    Live Sample · GitHub

    detached (detached signature)

    A separate signature file is generated that contains only the signature for the document.
    The document itself is not included in the container.

    Live Sample · GitHub

    attached (attached signature)

    A single container is generated that includes: original document and signature for the document

    Restriction

    An attached signature can be created for files up to 30 MB. For larger files use a detached signature. See File size.

    Mass operation

    Live Sample · GitHub

    The user can sign the files of several rows at once with a bulk operation, see Bulk signing and encrypting.

    How to add?

    Example

    Step 1 Add a mass action to the corresponding Service. The files created on the frontend come with each row: mass.getOption(MassOptionType.SIGNATURE_FILE_ID), mass.getOption(MassOptionType.SIGNATURE_FILE_NAME).

        @Override
    public Actions<MyexampleDTO> getActions() {
        return Actions.<MyexampleDTO>builder()
                .action(act -> act
                        .action("massDocumentSign", "Mass Document Sign")
                        .massInvoker((bc, data, ids) -> {
                            // only the rows signed on the frontend, the others get the frontend errors automatically
                            var massResult = data.getMassIds_().stream()
                                    .map(mass -> {
                                        Myexample entity = myexampleRepository.getReferenceById(Long.parseLong(mass.getId()));
                                        entity.setFileSignId(mass.getOption(MassOptionType.SIGNATURE_FILE_ID));
                                        entity.setFileSign(mass.getOption(MassOptionType.SIGNATURE_FILE_NAME));
                                        entity.setStatus(StatusSignEnum.SIGNED);
                                        return MassDTO.success(mass.getId());
                                    })
                                    .collect(Collectors.toSet());
                            data.getMassErrors_().forEach(error ->
                                    log.warn("Row {} was not signed: {}", error.getId(), error.getErrorMessage()));
                            return new MassActionResultDTO<MyexampleDTO>(massResult);
                        })
                )
                .build();
    }

    Step 2 In doUpdateEntity of the corresponding Service, when the encrypted file and the signature come, put the three files into a zip archive and save it to the field of the archive.

        @Override
    protected ActionResultDTO<MyexampleDTO> doUpdateEntity(Myexample entity, MyexampleDTO data, BusinessComponent bc) {
        setIfChanged(data, MyexampleDTO_.status, entity::setStatus);
        setIfChanged(data, MyexampleDTO_.fileSignId, entity::setFileSignId);
        setIfChanged(data, MyexampleDTO_.fileSign, entity::setFileSign);
        setIfChanged(data, MyexampleDTO_.fileEncryptId, entity::setFileEncryptId);
        setIfChanged(data, MyexampleDTO_.fileEncrypt, entity::setFileEncrypt);
        setIfChanged(data, MyexampleDTO_.fileEncryptAndSignId, entity::setFileEncryptAndSignId);
        setIfChanged(data, MyexampleDTO_.fileEncryptAndSign, entity::setFileEncryptAndSign);
        setIfChanged(data, MyexampleDTO_.fileId, entity::setFileId);
        setIfChanged(data, MyexampleDTO_.file, entity::setFile);
        if (data.isFieldChanged(MyexampleDTO_.fileEncrypt)
                && data.isFieldChanged(MyexampleDTO_.fileSign) &&
                !data.getFileSign().isEmpty() && !data.getFileEncrypt().isEmpty()) {
            String zipName = entity.getFile().substring(0, entity.getFile().indexOf('.')) + ".zip";
            String uploadId = uploadZip(zipName, entity.getFileId(), entity.getFileEncryptId(), entity.getFileSignId());
            entity.setFileEncryptAndSignId(uploadId);
            entity.setFileEncryptAndSign(zipName);
        }
        return new ActionResultDTO<>(entityToDto(bc, myexampleRepository.save(entity)))
                .setAction(PostAction.refreshBc(bc));
    }

        @SneakyThrows
    private String uploadZip(String zipName, String... fileIds) {
        var zipBytes = new ByteArrayOutputStream();
        try (var zip = new ZipOutputStream(zipBytes)) {
            for (String fileId : fileIds) {
                FileDownloadDto file = cxboxFileService.download(fileId, null);
                zip.putNextEntry(new ZipEntry(file.getName()));
                try (InputStream content = file.getContent().get()) {
                    content.transferTo(zip);
                }
                zip.closeEntry();
            }
        }
        byte[] content = zipBytes.toByteArray();
        return cxboxFileService.upload(
                new FileDownloadDto(() -> new ByteArrayInputStream(content), content.length, zipName, "application/zip"),
                null
        );
    }

        @Override
    public Actions<MyexampleDTO> getActions() {
        return Actions.<MyexampleDTO>builder()
                .action(act -> act
                        .action("massDocumentEncryptSign", "Mass Document Encrypt Sign")
                        .massInvoker((bc, data, ids) -> {
                            // only the rows processed on the frontend, the others get the frontend errors automatically
                            var massResult = data.getMassIds_().stream()
                                    .map(mass -> {
                                        Myexample entity = myexampleRepository.getReferenceById(Long.parseLong(mass.getId()));
                                        entity.setFileEncryptId(mass.getOption(MassOptionType.ENCRYPTED_FILE_ID));
                                        entity.setFileEncrypt(mass.getOption(MassOptionType.ENCRYPTED_FILE_NAME));
                                        entity.setFileSignId(mass.getOption(MassOptionType.SIGNATURE_FILE_ID));
                                        entity.setFileSign(mass.getOption(MassOptionType.SIGNATURE_FILE_NAME));
                                        entity.setStatus(StatusEncryptSignEnum.SIGN_ENCRYPT);
                                        return MassDTO.success(mass.getId());
                                    })
                                    .collect(Collectors.toSet());
                            return new MassActionResultDTO<MyexampleDTO>(massResult);
                        })
                )
                .build();
    }
