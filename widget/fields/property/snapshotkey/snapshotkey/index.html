    History of field changes

    Live Sample · GitHub

    snapshotKey turns on the history mode of a field: the field shows the difference between the previous (snapshot) value and the current value.

    • the previous value is taken from the field of the same record whose name is set in snapshotKey;
    • the current value is taken from the field set in key.

    Basic

    Live Sample

    This function is available for:

    • FileUpload
    • Input
    • Text
    • Hint
    • Number
    • Money
    • Percent
    • Date
    • DateTime
    • DateTimeWithSeconds
    • PickList
    • InlinePickList
    • Dictionary
    • Radio

    The history is shown in the widgets that show the fields of a record:

    • List
    • Info
    • Form
    • AdditionalInfo
    • AdditionalList;
    • GroupingHierarchy
    • Tree
    • FormPopup
    • PickListPopup

    Both values are taken from the same record (DTO) that the backend sends to the frontend:

    • current value - the DTO field set in key. It is the usual value of the field: it is edited and saved as usual;
    • previous (snapshot) value - the DTO field set in snapshotKey. It is a separate field of the same DTO with the same type as the current value.

    CXBox does not keep the history of changes and does not fill the previous value itself. "Previous value" is any value that the application wants to compare the current value with, and the application decides where it comes from, for example:

    • the value at a certain moment: before the document was sent for approval, at the previous version, at the last export;
    • the value from an audit (history) table or from another system;
    • the value of a related record (for example, the parent or the original record that was copied).

    The frontend only compares the two values and shows the difference. It does not change the previous value: when the current value is saved, the previous value stays as the backend sends it.

    In the sample each field of the entity has a pair of columns: the current value (inputField) and the previous value (inputFieldSnapshot). The previous values are filled by the test data and are not changed on save: doUpdateEntity changes only the current values.

    How to add?

    Example

    The setting is the same in every widget: snapshotKey of the field and the field with the previous value with type hidden.

    How the field is shown depends on the previous and the current value:

    Previous value Current value How the field is shown
    A B previous value (red background, strikethrough) and current value (green background) next to each other
    A A current value as a usual read-only field
    empty B only current value (green background)
    A empty only previous value (red background, strikethrough)

    The previous value is shown with the same component as the field type: dates and numbers are formatted, dictionary shows its icon and so on.

    Exception

    Text field

    For the text field type changes are shown word by word inside one text: deleted words have a red background and are struck through, added words have a green background.

    How to add?

    Example

    Step 1. Add the field with the previous value to DTO. It must have the same type as the main field. The value is sent to the frontend in the same record, the frontend does not request it separately.

       private String inputField;

   private String inputFieldSnapshot;

   private String textField;

   private String textFieldSnapshot;

   private String hintField;

   private String hintFieldSnapshot;

   private Long numberField;

   private Long numberFieldSnapshot;

   private Double moneyField;

   private Double moneyFieldSnapshot;

   private Long percentField;

   private Long percentFieldSnapshot;

   private LocalDateTime dateField;

   private LocalDateTime dateFieldSnapshot;

   private LocalDateTime dateTimeField;

   private LocalDateTime dateTimeFieldSnapshot;

   private LocalDateTime dateTimeWithSecondsField;

   private LocalDateTime dateTimeWithSecondsFieldSnapshot;

   private Boolean checkboxField;

   private Boolean checkboxFieldSnapshot;

   private Long pickListFieldId;

   private String pickListField;

   private String pickListFieldSnapshot;

   private Long inlinePickListFieldId;

   private String inlinePickListField;

   private String inlinePickListFieldSnapshot;

   private CustomFieldEnum dictionaryField;

   private CustomFieldEnum dictionaryFieldSnapshot;

   private CustomFieldEnum radioField;

   private CustomFieldEnum radioFieldSnapshot;

    Step 2. Add snapshotKey to the field in .widget.json. The value of snapshotKey is the name of the DTO field with the previous value.

    Step 3. Add the field with the previous value to the same .widget.json with type hidden. The backend sends to the frontend only the fields of the widgets, snapshotKey is not taken into account: without the hidden field the previous value is not sent, and the field is shown as not changed.

    A file is set by two values: the name of the file (key) and the id of the file (fileIdKey). The previous file is set the same way: its name in snapshotKey and its id in snapshotFileIdKey.

    Info

    Unlike the other field types, a FileUpload field with snapshotKey is not made read-only. The history is shown only when the field is read-only, for example in List and Info. An editable FileUpload field is shown as the usual upload with the current file.

    The field shows the previous file (red background, strikethrough) and the current file (green background). Both files can be downloaded. The files are compared by id: if the id of the previous file is the same as the id of the current file, the field is shown as usual.

    Without snapshotFileIdKey the history mode is off: the field shows only the current file as usual, the name from snapshotKey is not shown.

    How to add?

    Example

    Step 1. Add the name and the id of the previous file to DTO next to the name and the id of the current file.

    Step 2. Add snapshotKey and snapshotFileIdKey to the field in .widget.json and add both fields of the previous file to the widget with type hidden.

    === "snapshotKey and snapshotFileIdKey"
    === "Only snapshotKey"

    Features

    The previous value is sent only as a field of the widget The backend sends to the frontend only the fields that are used in the widgets of the view. The field from snapshotKey is not added automatically: add it to the widget as a field with type hidden.

    The field is always read-only

    Live Sample

    A field with snapshotKey is always shown in read-only mode, even in the Form widget and even if the field is enabled in row meta (setEnabled). FileUpload is an exception, see FileUpload.

    To edit the value, show the field in another widget without snapshotKey. In the sample the left Form has snapshotKey, the right Form has no snapshotKey and is used to change the current values.

    Values that are not saved yet Whether the difference is shown is decided by the record data received from the backend (saved values). The current (green) value is shown together with the changes that are not saved yet: if the value is changed in another widget of the same record, the green value changes at once, and the previous value stays as it was until the record is saved.

    Empty value: 0 Before the comparison both values are converted to strings, and 0 and null are treated as an empty value. Because of this for number, money, percent the previous value 0 is not shown, the current value 0 is not shown.

    Values are compared as strings The previous and the current values are compared as strings, exactly as they are received from the backend:

    • the previous value must be sent in the same format as the current value. For example, for dates both values must have the same format (2025-01-10T00:00:00), otherwise equal dates are shown as changed;
    • for pickList and inlinePickList the displayed value (key) is compared, not the id of the selected record. Send the displayed value of the previous record in snapshotKey.

    drilldown works only for the current value, the previous value has no drilldown.
