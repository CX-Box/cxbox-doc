    CalendarYearList

    CalendarYearList widget shows the records as events of a year calendar: twelve months of a year, an event takes one whole day. It is used for the events of a day: holidays, deadlines, reports. For the events with a time, use CalendarList.

    Basics

    Live Sample · GitHub

    How does it look?

    A record is shown as an event by three fields of the widget:

    • a title field — the value shown in the event;
    • a start field and an end field — dateTime (or date) fields with the day of the event.

    The year calendar has rules for the data:

    • an event is one whole day: the start is the beginning of the day (00:00), the end is the end of the same day (23:59 for dateTime);
    • one event per day.

    When a record breaks the rules, the calendar is not drawn, see Incorrect data.

    options.calendar

    The fields of the event are set in options.calendar of .widget.json.

    Example
    Property Type Default Description
    valueFieldKey String value Name of the field shown as the title of the event.
    startFieldKey String start Name of the field with the start of the event.
    endFieldKey String end Name of the field with the end of the event.

    How to add?

    Example

    Step1 Create DataResponseDTO with the title field and the start and end fields. The start and end fields have @SearchParameter: the calendar filters the records by the shown year. 

    @Getter
@Setter
@NoArgsConstructor
public class MyExampleBcDTO extends DataResponseDTO {


    @SearchParameter(name = "customField")
    private String customField;

    @SearchParameter(name = "startDateTime", provider = DateTimeValueProvider.class)
    private LocalDateTime startDateTime;

    @SearchParameter(name = "endDateTime", provider = DateTimeValueProvider.class)
    private LocalDateTime endDateTime;

    public MyExampleBcDTO(MyExampleBc entity) {
        this.id = Optional.of(entity).map(BaseEntity::getId).map(String::valueOf).orElse(null);
        this.customField = entity.getCustomField();
        this.startDateTime = entity.getStartDateTime();
        this.endDateTime = entity.getEndDateTime();
    }

}

    Step2 Fill the start and the end of the events by the boundaries of a day. 

            // an event of the year calendar is one whole day: from 00:00 to 23:59, one event per day
        int year = LocalDate.now().getYear();
        saveDayEvent("Meeting 1", LocalDate.of(year, 2, 10));
        saveDayEvent("Meeting 2", LocalDate.of(year, 4, 22));
        saveDayEvent("Conference", LocalDate.of(year, 6, 17));
        saveDayEvent("Release", LocalDate.of(year, 9, 3));
        saveDayEvent("Annual report", LocalDate.of(year, 12, 15));

    Step3 Add fields.enableFilter for the start and end fields to corresponding FieldMetaBuilder. 

    @Service
public class MyExampleBcMetaBuilder extends FieldMetaBuilder<MyExampleBcDTO> {

    @Override
    public void buildRowDependentMeta(RowDependentFieldsMeta<MyExampleBcDTO> fields, InnerBcDescription bcDescription, Long id, Long parentId) {
        fields.setEnabled(MyExampleBcDTO_.endDateTime);
        fields.setEnabled(MyExampleBcDTO_.startDateTime);
        fields.setEnabled(MyExampleBcDTO_.customField);
        fields.setEnabled(
                MyExampleBcDTO_.id
        );
    }

    @Override
    public void buildIndependentMeta(FieldsMeta<MyExampleBcDTO> fields, InnerBcDescription bcDescription, Long parentId) {
        fields.enableFilter(MyExampleBcDTO_.endDateTime);
        fields.enableFilter(MyExampleBcDTO_.startDateTime);
        fields.enableFilter(MyExampleBcDTO_.customField);
        fields.enableFilter(
                MyExampleBcDTO_.id
        );
        fields.enableSort(
                MyExampleBcDTO_.id
        );
    }

}

    Step4 Create file .widget.json with type = "CalendarYearList". Add the fields of the event and options.calendar. 

    {
  "name": "myexample",
  "title": "CalendarYearList widget",
  "type": "CalendarYearList",
  "bc": "myExampleBc",
  "fields": [
    {
      "title": "Custom Field",
      "key": "customField",
      "type": "input"
    },
    {
      "title": "Start Date Time",
      "key": "startDateTime",
      "type": "dateTime"
    },
    {
      "title": "End Date Time",
      "key": "endDateTime",
      "type": "dateTime"
    }
  ],
  "options": {
    "calendar": {
      "valueFieldKey": "customField",
      "startFieldKey": "startDateTime",
      "endFieldKey": "endDateTime"
    },
    "layout": {
      "rows": [
        {
          "cols": [
            {
              "fieldKey": "customField",
              "span": 12
            }
          ]
        }
      ]
    }
  }
}

    Step6 Set the page limit of the business component to the number of events of a year, for example 1000. When the business component has more records than the limit, the widget shows only the table. See Page limit. 

    BC;PAGE_LIMIT;MASS_PAGE_LIMIT;SORT;FILTER;ID
myExampleBc5039;1000;NULL;NULL;'""';

    Title

    Info

    Title is not available in this release: the widget does not show a title.

    Color

    The color of the events is set for the title field of the event (valueFieldKey), as in CalendarList: bgColorKey for a calculated color, bgColor for a constant color.

    Business component

    This specifies the business component (BC) to which this widget belongs. A business component represents a specific part of a system that handles a particular business logic or data.

    see more Business component

    Show condition

    • no show condition - recommended: widget always visible

    Live Sample · GitHub

    • show condition by current entity, show condition by parent entity: as in CalendarList.

    Tips

    It is recommended not to use Show condition when possible, because wide usage of this feature makes application hard to support.

    Fields

    Fields Configuration. The fields array defines the fields of the event (see options.calendar), the fields available for filtration and the columns of the table mode.

    {
    "title": "Custom Field",
    "key": "customField",
    "type": "input"
}
    • "title"

    Description: Field Title.

    Type: String(optional).

    • "key"

      Description: Name field to corresponding DataResponseDTO.

      Type: String(required).

    • "type"

    Description: Field types. The start and end fields: date, dateTime or dateTimeWithSeconds. The type sets how exactly the boundaries of the day are checked: to a day, a minute or a second.

    Type: String(required).

    Options layout

    options.layout - no use in this type.

    Actions

    Actions show available actions as separate buttons above the calendar see more Actions.

    A click on an event selects the record. The actions of the record are in the three-dot menu that appears when the mouse is over the event.

    The form widget of options.edit opens at the event on click, as in CalendarList. When a record is created, the widget switches to the table mode.

    Additional properties

    Customization of displayed columns

    not applicable: the calendar has no columns.

    Year navigation

    The years of the calendar are its pages: the arrows go to the next and the previous year, "Today" returns to the current year. The months of the year are scrolled inside the widget; on opening, the calendar is scrolled to the current month. The records of the shown year are requested with the filters by the start and the end fields.

    Filtration

    The fields of the widget with a filter are shown above the calendar; the start and the end fields of the event are not shown there, the shown year filters the records by them.

    see more Filtration

    Drilldown

    The title field can have a drilldown: a click on the title of the event opens the link. see more DrillDown

    Table mode

    The settings icon of the widget opens the Mode menu with Calendar and Table. In the table mode the widget shows the records as a table with a column per field of the widget. After the switch back to the calendar, the calendar shows the year of the filter of the table.

    Incorrect data

    When a record of the shown data breaks the rules — the start or the end is empty, the event is not one whole day, or a day has two events — the calendar is not drawn: the widget opens in the table mode, the Calendar mode is disabled and a warning icon shows There is incorrect data, only table mode is available.

    Page limit

    When the business component has more records than the page limit, the calendar is not drawn: the widget opens in the table mode, the Calendar mode is disabled and a warning icon explains why. see more Page limit
